## 1. Project overview

**ZICKONEZERO** is a statically exported portfolio and case-study site for Michael Zick / ZICKONEZERO Creative. It presents project work, case studies, product/service pages, and analytics-instrumented navigation/CTA flows.

Primary flows:
- Home portfolio: a living neon city the visitor walks through on scroll, from a weathered futuristic alley past a holo billboard and three work districts to an open stretch of city above the footer (a giant carp streamer flies from the top of a rooftop mast there at night over a string of paper lanterns, with police drones patrolling behind it, and by day a sightseeing airship drifts across among clouds and delivery drones over rooftops where a window washer works), with a minimap HUD for fast travel and a lightbox gallery.
- Case studies: reusable project showcase layouts for DemoStoke, Antisyphon Training, Nice Guy University, and related work.
- Product/service pages: DemoStoke, DemoStoke Fleet Ops, Find Your Flow State, Who's In Charge, Riptyde, TimeFraim, 12 Step Meetings, Bars of Sand, and about pages.
- Hidden Bar Four: the hero's "BAR FOUR" sign links to `/bar-four`, a basement listening bar, record exchange, and club whose booth holds the house rack, a playable Rackloose modular synth. It is open only at night and kept out of the sitemap and search results.
- Contact: `/contact` posts to the Cloudflare Worker in `workers/contact/` (deployed at `https://zickonezero-contact.zickonezero.workers.dev/api/contact`), which relays through Brevo SMTP.
- Static publishing: `next build` exports the site with `output: 'export'` and regenerates `public/sitemap.xml`.

## 2. Tech stack

- **Framework:** Next.js 15 Pages Router with React 19 and TypeScript.
- **Rendering:** Static export via `next.config.js` (`output: 'export'`, `trailingSlash: true`, unoptimized images).
- **State:** Redux Toolkit with typed hooks in `src/hooks.ts`.
- **Styling:** styled-components 5, SCSS globals, and shared theme constants in `styles/theme.ts`. Fonts (Orbitron, Rajdhani, Share Tech Mono) are self-hosted from `@fontsource` packages through `next/font/local`.
- **UI libraries:** Radix UI icons/select/tabs, `fslightbox-react` (loaded on a gallery's first open through `src/components/LazyLightbox.tsx`).
- **Analytics:** Google Tag Manager plus Mixpanel, with the event helpers (`trackEvent`, `trackLinkClick`, `trackPageView`) and the Mixpanel loader in `src/lib/analytics.ts`. `src/components/SiteAnalyticsScripts.tsx` starts both only `ANALYTICS_DELAY_MS` (4 seconds) after the window's load event (`src/hooks/usePageSettled.ts`): GTM through next/script `lazyOnload` at an idle moment, and Mixpanel through `loadMixpanel`. Together they block a phone's main thread for about half a second, which had been most of the homepage's Total Blocking Time; Lighthouse's default simulated run stops recording about a second after load, so it no longer counts them. A visitor who leaves within those first seconds is not recorded. `loadMixpanel` follows michaelzick.com's setup: once per document, and only on the canonical host (`SITE_URL`'s hostname, so local dev, workers.dev, and branch previews send nothing) with a token set, it installs the official snippet stub (`__SV`, `_i`), which the CDN bundle (`cdn.mxpnl.com/libs/mixpanel-2-latest.min.js`) requires, appends the script, and calls `init` on load; a failed or 30-second-late download gives up. The token is `NEXT_PUBLIC_MIXPANEL_TOKEN` or, without it, the project token hard-coded as the `MIXPANEL_TOKEN` fallback (public by design); the project is US-resident, so the init sets no `api_host`. The init turns off automatic page views and broad autocapture (the site tracks its own events) and records every session with heatmaps; replays mask form inputs but keep the public copy and screenshots readable, skip console logs, and block Bar Four's rack below its header (its patch and preset names), which `RacklooseBooth` marks with `data-rackloose`. There is no consent UI. Right after `init`, `startMixpanel` registers a `release` super property, the `package.json` version that `next.config.js` inlines as `NEXT_PUBLIC_RELEASE_VERSION`, so every event names the production release it came from. Events tracked before Mixpanel starts (the first `page_view`, an early click) wait in a bounded, in-order queue of 50, flushed right after `init` and that `register`; once Mixpanel won't load, nothing waits.
- **Tooling:** npm, Node 24.x, Jest + React Testing Library, ESLint, TypeScript. An optional Playwright smoke test runs only on request (Playwright is not a project dependency).

## 4. Application structure

### 4.1 Next app

- **Root wrapper:** `pages/_app.tsx` imports global SCSS, wraps pages with Redux and `AppThemeProvider`, sets the self-hosted font variables (`src/theme/FontVariables.tsx`) and the time-of-day `theme-color` meta (`src/theme/ThemeColorMeta.tsx`), mounts `SiteAnalyticsScripts` (GTM and Mixpanel, deferred until after load) and `PageAnalytics`, and renders only the shared viewport plus icon/manifest links in `<Head>`. It mounts the persistent city once, outside the page, so it stays alive across navigation: `CityBackdrop` (its camera follows `router.pathname`), `WeatherCanvas` (daytime dust, or snow night and day on About; dimmed off the homepage), and `FastTravelTransition`. Pages and shared components read the normalized route from `CurrentPathContext` (`src/hooks/useCurrentPath.ts`) instead of `useRouter()`, which throws outside a mounted router.
- **Per-page SEO:** every page renders its own `<Seo>` (`src/components/Seo.tsx`) for the title, canonical (trailing-slash, absolute), description, Open Graph/Twitter tags, and JSON-LD. Metadata copy lives inline per page; `ProjectShowcase` pages single-source `title`/`summary`/`heroImage` into local consts shared by `<Seo>` and `<ProjectShowcase>`. There is no global head/meta component. A `noIndex` page (404, Bar Four) gets the robots meta and no canonical. JSON-LD is serialized with `<` escaped, and every Person node (the homepage's Person, the About and Contact main entities, and case-study authors) shares `PERSON_ID` (`https://www.zickonezero.com/#person`) and the trailing-slash home URL. The homepage has its own description naming Michael Zick. All page social images declare their actual dimensions and descriptive alt text; the default share image, `public/img/og/zickonezero-card.png`, is a 1200x630 card with the ZICKONEZERO logo (a cyan Z and magenta 1 enclosed in a chamfered cyan zero) beside the wordmark, "CREATIVE", a short divider in the logo's cyan, and Michael Zick's name and disciplines, on the logo's own near-black background. The wordmark and "CREATIVE" are set exactly like the hero h1's (Orbitron 900, the magenta ONE, and the hero's tracking, line heights, and gaps, scaled up); `scripts/render-share-card.js` repaints only that text band and the divider onto the committed card, so the logo and name lines stay pixel-identical. The logo's 1254px master is `public/img/brand/zickonezero-mark-v4.png`; the favicons, Apple touch icon, and manifest icons in `public/img/favicon/` are exports of it, kept at their existing URLs.
- **Document:** `pages/_document.tsx` handles server document structure for styled-components, renders each route's neon accent into `<html data-accent>` from `getRouteMeta`, and runs `THEME_BOOTSTRAP_SCRIPT` (`src/theme/themeConfig.ts`) at the top of `<body>` so a stored day choice applies before first paint.
- **Home page:** `pages/index.tsx` loads work data with `getStaticProps`, syncs it into Redux via `useEffect`, and passes it to `MainContent` as a prop. `MainContent` reads the store only when no prop is passed, so that post-hydration sync doesn't re-render the city.
- **Content pages:** top-level files in `pages/` render about, contact, case-study, DemoStoke, Antisyphon, Nice Guy University, product pages, and the hidden `bar-four` page.
- **Contact page:** `pages/contact.tsx` renders `src/components/ContactContent.tsx`, which posts JSON to `NEXT_PUBLIC_CONTACT_ENDPOINT` (default `DEFAULT_CONTACT_ENDPOINT`, the deployed workers.dev URL) via `src/lib/contactForm.ts`, tracks `contact_form_submit_*` events, and includes a honeypot `website` field.
- **Static export:** `next.config.js` keeps the app static-host friendly. Static data helpers live under `src/` instead of `pages/api` so the exported site does not expose accidental API routes.

### 4.2 State, content, and UI

- **Redux store:** `src/store.ts` combines `worksDataSlice` and `showMobileMenuSlice`.
- **Typed hooks:** `src/hooks.ts` exports `useAppDispatch` and `useAppSelector`.
- **Homepage:** `src/components/MainContent.tsx` composes the walk through the city from `src/components/home/`: `HeroScene` (a sticky 3D alley with the single h1 "Michael Zick is ZICKONEZERO Creative" in a large bottom-left HUD panel and a tube-neon "BAR FOUR" sign (the word spelled out, never the numeral) at the top right, with a plain Cyrillic "БАР ЧЕТЫРЕ" caption (`lang="ru"`) and a "Downstairs" arrow, that is a link to the hidden Bar Four. The link comes after the introduction's CTAs in the DOM, takes its accessible name "Bar Four" from a visually hidden label (the flickering tube letters, caption, and arrow are `aria-hidden`), brightens and steadies on hover or focus, and is unlit by day; scrolling writes `--p` from 0 to 1 to walk the camera in), `HoloBillboard` (a sticky tower screen that pans through product screenshots, its tower shaded dark in both themes so the screenshots stand out), three `District`s, and `CityGapScene` (`styles/cityGap.ts`), a decorative, `aria-hidden` stretch at least a screen tall before the footer, where the persistent city shows through behind one giant foreground piece. At night it is `KoiStreamer`, an original giant carp streamer flying from the top of a mast on a rooftop, its mouth hoop just under a spinning arrow wheel, so the carp is the focal point. The carp wears the airship's 夢 (`lang="ja"`) on a crest behind its gills and "I DREAM OF THE FEATURE" in gold on a dark sash along its side; nothing else at night is lettered. The carp is drawn once (geometry in `src/lib/city/koi.ts`) and shown through a chain of nested links, each an `<svg viewBox>` window onto the shared drawing that rotates about its front joint on the centerline: the static droop is the `rotate` property and the swing is staggered `transform` keyframes, so a wave runs from mouth to tail with nothing repainted. Each window ends in a notch just past the next joint, which fills the wedge the bend opens there; the notch's `clip-path` starts outside the box, because a clipped edge across the fabric lets the fills beneath show through as a hairline. The scales sit in columns clear of the joints, and the carp is outlined in dark, so the sub-pixel steps at the joints stay dark on dark. In portrait the carp hangs lower and longer, so it stays giant in a tall frame. Below and behind the carp, nine paper lanterns (vermilion and amber, drawn once and shown through `<use>`, each with a steady glow) hang from a cord slung from the mast to a tower across the street; each sways a little from its hook. The cord's shape and the lanterns' drops come from `LANTERN_CORDS` and `lanternString` in `koi.ts`, which `styles/cityGap.ts` imports too: on wide screens the cord spans 1120 carp units (at most 65% of the width) and falls toward a bracket on the tower's face under the carp's own droop, so the tail clears it at its lowest swing at every width; on tall screens it runs level to a post on the tower's roof. `NightRooftops` adds that tower (water tank, antenna with a steady red beacon, an unlit blade sign) and a mid-rise beside the carp's rooftop, laid out in carp units, whose roof never rises closer than the lanterns allow. Every window on them is fixed and steady. `PoliceDrones` flies two original police quadcopters behind the carp, the lanterns, and the buildings: one westbound high above the carp and one eastbound low over the roofs, sharing a 30-second loop half a loop apart, so they are never on screen together. Each is pitched into its flight with a faint static searchlight, and its light bar flashes red, then blue (see Motion safety). By day it is `Airship`, a sightseeing airship that drifts across the sky on its own, nose first, on a 64-second loop, with spinning props, its 夢 emblem, and an LED band scrolling "I dream of the feature"; its still frame is centered. Around it, `DayClouds` drift slowly left to right behind the airship, `DayDrones` (three quadcopters, each on its own timing, pitched forward with a parcel swaying on a short tether, their rotors drawn as motion blur so nothing spins) fly left to right between it and the roofs, and `DayRooftops` fills the foreground with a row of teal rooftops (a water tower, bulkheads, AC units, and an antenna) at least the viewport wide (200vw in portrait, sunk a quarter in short landscape so it stays below the airship). A window washer's gondola, placed in the roofs' own box so it stays on its building, works down the tallest one and back on a 36-second loop, its cables scaling with it. Neither scene has floating text: every word is on the carp or the airship. Both are in the static HTML and the theme shows one; only transform animates, on layers around static SVG, and `useSceneMotion` pauses them offscreen and in hidden tabs and stills them under reduced motion or Save-Data. The hero's pitch is "I dream of the feature." and its CTAs are "See Case Studies" and a "Contact" link. Its narrow, asymmetric street has worn paving, drains, service doors, pipes, patched shutters, and refuse drawn by the hero-only `AlleyDetails.tsx`; floor details share the street plane to avoid z-fighting. The overhead LED marquee is replaced by five original vertical megastructures in `AlleyTowers.tsx`, beyond the alley walls on the same 3D camera track. Their staggered opacity and window detail follow `--p`, peaking near the end of the walk; masked bases dissolve into ground fog without animated blur, and scrolling backward restores the same view. Reduced motion shows a still, visible skyline. A patrol drone recedes along the alley toward the towers and fades out in the distance; its animation shares the scene visibility lifecycle. Pointer movement only affects camera parallax, with no cursor glow. Eight fixed paper scraps (four on phones) move in small CSS gusts. `useSceneMotion.ts` writes `data-scene-motion` without React state, pausing ambient animations offscreen or in hidden tabs and leaving paper still under reduced motion or Save-Data; it cleans up its observer and visibility/connection listeners. Facade palette overrides stay local to the hero so the billboard is unchanged. It also owns lightbox state (the gallery is a `LazyLightbox`), mobile menu state, analytics events, and the active district, which sets the city glow through `setCityAccent` (magenta, cyan, then amber). Each district (Case Studies, Product Engineering, Web Development) is a glass city block tinted by the muted `--home-section-{case,product,web}-{bg,border}` tokens in `styles/globals.scss` (night defaults with day overrides) and wraps a `GridContent` grid of gig cards. A card's hover glitch layers set `background-image: var(--thumb)` only inside its fine-pointer hover rule (`styles/district.ts`): a background image downloads even at opacity 0, which fetched every card image at load and defeated the `<img>`'s lazy loading. Passing `carouselLabel` to `GridContent` turns its grid into a labelled horizontal scroll-snap carousel at phone width, with prev/next buttons driven by `src/hooks/useHorizontalGallery.ts`. `HomeHud` is the "Homepage sections" nav: a minimap with district pins, a player arrow that walks the route on scroll, a clock, and a quest tracker on wide screens (a red "Next destination" label over a yellow objective button, underlined at rest so it reads as a link, whose underline fades out on hover or focus; its objective advances from "Head to Case Studies" to "Head to Product Engineering" to "Head to Web Development", then "Return to surface" at Web Development; the final button uses the same eased jumper to return to scroll position zero and reset the active district), or the same buttons as a bottom bar on narrow or short screens. Its fast travel uses the eased, interruptible jumps in `src/lib/city/scroll.ts` and lands on the unchanged district heading ids (`case-studies`, `ux-design`, `web-development`).
- **Living city modules:** `src/lib/city/` is framework-free and holds the engine: `prng.ts` (seeded generators), `skyline.ts`/`facade.ts`/`minimap.ts`/`recordWall.ts` (procedural SVG geometry as a few path strings with integer coordinates), `koi.ts` (the end scene's carp drawing, the windows its links show, and the lantern cord's shapes and lantern drops, rounded to tenths), `routes.ts` (each route's fast-travel label, accent, and skyline camera position), `accent.ts`, `scrollSignal.ts` (one shared rAF-throttled scroll listener that never re-renders React), `scroll.ts`, `weather.ts` (batched canvas rain, dust, and snow; the site draws dust, and snow on About), and `sound.ts`/`ambience.ts`/`streetSounds.ts`. Every layout decision comes from a fixed seed so the static HTML matches hydration; keep `Math.random` for post-mount visuals only. `src/components/city/` renders the persistent scenery (`CityBackdrop`, `Skyline`, `FlyingTraffic`, `WeatherCanvas`, `FastTravelTransition`) and the signage (`AlleyWall`, `NeonSign`, `LedTicker`); `src/components/hud/` holds `HudClock`, `QuestTracker`, `ScrambleText`, `TimeOfDayToggle`, and `SoundToggle`. Decorative scenery, Japanese signs (marked `lang="ja"`), and HUD readouts are `aria-hidden`; headings, links, and buttons keep their real text, and `NeonSign` keeps a heading's exact accessible name by rendering letters as inline spans.
- **Day, night, sound, and fonts:** night (`dark`) is the default city and day (`light`) is the visitor's opt-in, stored as `zickonezero-theme`; anything else, including the retired `system` value, resolves to night. `src/theme/ThemeContext.tsx` toggles it with a view-transition crossfade (`document.startViewTransition`, timed by the `::view-transition-*(root)` rules in `styles/globals.scss`); without View Transitions support or under reduced motion the switch is instant. Do not animate the color tokens themselves: transitioning inherited custom properties on `:root` restyles and repaints the whole homepage every frame, which stalled and flashed it. Sound is muted by default, stored as `zickonezero-sound`, and only starts from a click, tap, or key press; the synthesized Web Audio graph in `src/lib/city/ambience.ts` loads the first time sound is turned on. It runs a steady murmur and traffic drone (at night, two formant-synthesized voices talk down the street; the day has no voices), and a lookahead scheduler books one-off sounds from `src/lib/city/streetSounds.ts` on the audio clock at random gaps: by day, passing cars (now and then a truck or scooter), horns that are sometimes answered, and birdsong; at night, a late car, wind gusts, crickets, and, far off and never overlapping, a siren, a helicopter, or an elevated train. Every street sound is placed at a distance (quieter, duller, and wetter in a synthesized street echo the farther away it is), is metered to peak about 7 to 14 LU under the bed so it stays subtle, and unplugs itself when it ends. Keep it that way: an earlier neon buzz read as honking and loud white-noise car passes read as static. Switching the time of day crossfades the beds and lets the new hour's sounds arrive staggered, and browsers without Web Audio drop the toggle after hydration. Bar Four keeps the street outside: it holds the ambience for the whole visit (see Bar Four below). The Orbitron (display), Rajdhani (HUD), and Share Tech Mono (readout) faces are defined in `src/theme/fonts.ts` and exposed on `:root` as `--font-display`, `--font-hud`, and `--font-mono`, so no font CDN is involved.
- **Motion safety:** reduced motion keeps every scene still and readable: the hero sets no `--p`, the billboard becomes a still wall of panels, weather draws one still frame (as it also does under Save-Data), the About hero's snow holds still, fast travel skips the shutters, in-page jumps are instant, and `ScrambleText` swaps text without the effect. `styles/globals.scss` also shortens every animation and transition under `prefers-reduced-motion`. Neon power-on follows WCAG 2.3.1: no dip goes fully dark and nothing flashes more than three times a second (see `styles/neon.ts`). There is no rain at night: `WeatherCanvas` hides itself after dark except on About, where light snow falls in both themes (it draws daytime dust elsewhere); the hero has no near-rain or steam layers, and the ambient sound (`src/lib/city/ambience.ts`) has no rain hiss, because those full-screen night layers pushed Chrome to drop and redraw the page, which flickered after scrolling to the bottom and back up. The Bar Four sign deliberately gives only its A and U three brief, shallow brightness dips per 4.8- or 6.3-second loop, separated by at least a second of steady light; the letters never go dark and remain steady under reduced motion or Save-Data. Its flicker pauses offscreen and in hidden tabs through `useSceneMotion`, stops while the sign is hovered or focused, and is off by day. All other neon letters, the billboard screen, and beacons stay steady after they power on, since broad recurring dips read as rendering glitches, especially at night. Window lights stay steady day and night: switching single lights off and on repainted the full-screen skyline layers, which flickered in Chrome, so `generateSkyline`'s `flickerCount` picks are not drawn (they stay only because the mid layer's signs are placed after them in its seeded stream). The end scene's carp waves as a chain of rotating links and its lanterns sway, the night's police drones patrol, and by day its airship, clouds, drones, and gondola move on loops; all pause offscreen and in hidden tabs, and hold a still frame (the police drones parked in open sky, the airship centered, the delivery drones mid-flight, the gondola partway down) under reduced motion or Save-Data. The police lights are the end scene's only flashing: each light on a drone's bar is a small radial glow whose opacity alone animates (`will-change: opacity`, no color, shadow, or filter changes), red then blue half a 1.2-second cycle later, so under two flashes a second in all, with the drones never on screen together; under reduced motion or Save-Data both lights hold steady at half strength. Power-on effects (the `NeonSign` ignition, the billboard warming up, the gig cards booting) play only on the first page load: `pages/_app.tsx` calls `markCityStarted` (`src/lib/city/powerOn.ts`) after it mounts, later pages arrive already lit, and `src/hooks/usePowerOn.ts` arms standby in a layout effect and never for content already on screen, so client navigation, the back button, and restored scroll never blink content out and back in.
- **Inner pages:** the HUD primitives in `styles/hud.ts` (notched glass frames, scanlines, neon and HUD buttons, and the toggle buttons) dress the navigation, the homepage HUD, and the inner pages. `ProjectShowcase` opens on a holo-billboard hero, About is a dossier, Contact is a "secure channel" terminal (`styles/contact.ts`), and the 404 page (h1 "Page not found") shows a vitals monitor that flatlines. Each route glows in its own accent from `src/lib/city/routes.ts`: case studies magenta, product pages cyan, About violet, Contact and 404 red, Bar Four amber, and Home cyan.
- **Bar Four:** the name is a pun: in a four-bar phrase, bar four is the turnaround where the fill drops. `pages/bar-four.tsx` (`noIndex`, and skipped by the sitemap generator) renders `src/components/barfour/BarFourContent.tsx`, a basement club wired like a modular rack. Its decorative room (`styles/barFour.ts`) has a ceiling patch rail with cables slung between jacks in Rackloose's audio, CV, and gate colors; a seeded wall of record shelves (`src/lib/city/recordWall.ts`, one path per tone, with a few sleeves face-out at the sides); two speaker stacks (hidden below the small-tablet breakpoint); and a lit perspective dance floor. The wall, floor, and rail fade out at their sides into the city. Two moving heads sweep slow beams (rotation only). They pause offscreen and in hidden tabs through `useSceneMotion`, stay still under reduced motion or Save-Data, are hidden on phones, and are off by day. Over the room sit the tube-neon h1 "Bar Four" and the caption "БАР ЧЕТЫРЕ" (`lang="ru"`, `aria-hidden`). Below it, `RackBooth` is the booth (region "The House Music"), with no awning or sign above it. It has an "Open rack tonight" ticket stub, a link to the standalone studio at `https://rackloose.michaelzick.com/`, and a fixed-height deck holding the rack. The club is open only at night. By day, CSS on `html[data-theme]` drops a flight-case lid over the deck, with console tape reading "Closed. Doors open at dusk." and a **Wait for dark** button (tracked as `theme_toggle` from `bar_four`), so the static HTML never flashes the wrong state. The rack mounts only once the stored theme is known to be night; switching to day unmounts it and stops its audio. `RacklooseBooth.tsx` is loaded with `next/dynamic` (`ssr: false`), so Rackloose stays out of every other page and the static HTML. It seeds a first visit's autosave (`zickonezero.rackloose.patch.v1`) with the Neon Skyline preset, passes `keysEnabled` only while focus or the last pointer press is inside the rack (Rackloose listens for note keys and Space on the whole window), and tracks `bar_four_rack_engaged` on the first press inside it. `BarFourContent` calls `holdAmbience` (`src/lib/city/sound.ts`) when it mounts, by day or night, so none of the city's day or night sounds play in the club; it does not change the stored sound choice, and `releaseAmbience` on leaving brings the city back if the visitor has it on. Rackloose is installed from the pinned release archive in `vendor/rackloose/` (see `README.md`), and its package exports only an ESM `import` entry, so Jest tests mock it with `{ virtual: true }`.
- **Project showcases:** `src/components/ProjectShowcase.tsx` provides the reusable case-study shell with hero, section cards, lightbox, and tracking. The hero is the page's largest paint, so it is rendered with `visible` and `data-reveal='load'` in the static HTML and boots up from the first paint instead of waiting for hydration and an observer, while later sections still boot up as they scroll in. Its boot-up (`bootUpOpening` in `styles/projectShowcases.js`) keeps the settle, jitter, and scan line but drops the wipe and fades, and its image and text sit still: Chrome never credits Largest Contentful Paint to content first painted clipped or transparent, and an animated image counts only once its animation ends, which had put these pages' LCP at 10 to 18 seconds. The About hero and the case-study introductions do the same (`useAnimatedSections(resetKey, ['section-intro'])` starts them visible); the About hero's photo, a CSS background, is preloaded. Keep each opening hero image eager (case-study intro images use `loading='eager'`) with `fetchPriority='high'`, and anything in a hidden tab lazy. Opening hero images are served from `-640w`, `-960w`, `-1440w`, and `-1920w` copies beside the original (only those narrower than it, made with sharp at quality 80) through `heroImageSources` in `src/lib/responsiveImages.ts`, which holds each hero's natural width and the hero's `sizes`; the originals stay for share images and the lightbox. A new showcase whose hero is wider than 640px needs its copies and an entry there, which `__tests__/responsive-images.test.tsx` enforces. CI runs `npm ci`, `agent-briefs:check`, lint, typecheck, a `workers/contact` install + typecheck, tests (a step capped at 3 minutes), and production build on Node 24.x. CI never runs a browser. The **Browser tests** workflow (`.github/workflows/browser-tests.yml`) runs only when started by hand from the Actions tab: it builds the site, installs Playwright for that run, runs `npm run test:browser` (capped at 3 minutes), and uploads the screenshots as the `browser-screenshots` artifact.

Security automation runs Gitleaks, dependency review, CodeQL, and a production dependency audit at high severity (`npm audit --omit=dev --audit-level=high`). Next.js stays on the patched 15.5 release line with matching `eslint-config-next`; Sharp uses 0.35.5 or later. The root `package.json` overrides Next's pinned PostCSS with 8.5.28 for security fixes; retain that override until Next's own dependency is patched. The full audit's remaining findings are development-only (`braces` and `sprintf-js`, which have no patched releases, through Jest 29, Sass's file watcher, and `eslint-config-next`); clear them by upgrading those tools, not by forcing overrides.

**Releases:** every merge to `main` is a production release, versioned with semver read for a website: major for a redesign or rebuild, minor for new pages, case studies, or features, patch for fixes and copy. v1.0.0 is the living-city rebuild. The release PR (from the integration branch into `main`) bumps the version with `npm version X.Y.Z --no-git-tag-version`; once it merges and Workers Builds deploys it, tag the merge commit with `git tag -a vX.Y.Z <merge-sha> -m "<release title>"` (an optional message body becomes the release notes' opening) and `git push origin vX.Y.Z`. `.github/workflows/release.yml` then checks the tag with `scripts/check-release-tag.js`, checks it is on `main`, and publishes the GitHub release with the tag's title and the PRs merged since the previous tag. Production still deploys from `main`, not from tags; the tag records which commit went live, which is also how to pick a Cloudflare deployment to roll back to (the dashboard's Deployments or `npx wrangler rollback`). Repository rulesets protect both: **Main Branch Protection** requires a PR merged with a merge commit, blocks force-pushes and deletion, and requires the `checks` (CI), `Secret Scan`, `Dependency Audit`, `Dependency Review`, and `CodeQL Scan` checks; **Release tags** stops a `v*` tag from being moved or deleted once pushed.

The site is Cloudflare Worker `zickonezero`, serving `out/` from this repository's `main` branch through Workers Builds (Node 24, `npm run build`, `npx wrangler@4.133.0 deploy`). Non-production branches build with Node 24 and `npm run build`, then use `npx wrangler@4.135.0 preview` for a stable branch URL. The required empty `previews` block keeps previews isolated while reusing top-level static asset settings. Older branches must incorporate this configuration before preview builds can succeed. Root `wrangler.jsonc` configures custom domains `zickonezero.com` and `www.zickonezero.com`, static assets, trailing-slash handling, and `404-page` fallback. `public/_headers` and `public/_redirects` are applied by Cloudflare. `_headers` also gives `/_next/static/*` (content-hashed) a year-long `immutable` `Cache-Control`; images keep the default revalidating cache, because screenshots get replaced at the same URLs. Lighthouse SEO reads 69 on branch preview URLs because Cloudflare sends them `x-robots-tag: noindex`, which fails the crawlability audit alone; measure SEO on `https://www.zickonezero.com/`. `_redirects` 301s the removed `/michael-zick-coaching` route (bare, trailing-slash, and descendants) to `https://www.niceguyuniversity.com/`. Framing: the site sends neither `X-Frame-Options` nor CSP `frame-ancestors`, so any site can show it in a frame, as Nice Guy University can (the michaelzick.com landing page frames it in its Internet Search window). `__tests__/security-headers.test.js` guards this. The zone's **Canonical apex to www** Redirect Rule preserves path/query and uses HTTPS. The former DigitalOcean static component remains in shared app `demostoke` (`8b602f38-1268-4375-bef4-46d9001db792`) as an owner-managed rollback until archival; the migration does not archive that app. The legacy spec-transform script remains for rollback; keep raw specs outside the repo and use complete raw API specs with `update_all_source_versions: false` for hosting-only updates. The CSP allows the inline GTM/theme bootstraps and styled-components inline styles that the static export requires, Mixpanel's SDK and recorder from `https://cdn.mxpnl.com` and its ingestion on `https://*.mixpanel.com` (any data-residency host), and `blob:` in `script-src` for Rackloose's audio worklets: the Bar Four sign navigates on the client, so the homepage's policy is the one in force when the rack starts, and a path-scoped header would never apply. `__tests__/security-headers.test.js` guards this. Environment variables: `NEXT_PUBLIC_SITE_URL` / `SITE_URL` set the canonical origin (see `src/lib/siteConfig.js`); `NEXT_PUBLIC_MIXPANEL_TOKEN` overrides the public Mixpanel project token; `NEXT_PUBLIC_CONTACT_ENDPOINT` overrides the contact form endpoint (default is the deployed workers.dev URL; set it to `http://localhost:8787/api/contact` in `.env.local` when running the Worker locally).

## 6. Conventions

- **Runtime:** use Node 24.x and npm. Keep `package-lock.json` authoritative.
- **Pages:** add route files under `pages/`; top-level page filenames become routes and are picked up by the sitemap generator unless reserved or skipped.
- **Components:** use PascalCase component exports; keep route/page composition thin and move reusable behavior into `src/components`, `src/hooks`, or feature folders. Import components from their own files: there is no `src/components` barrel, because one pulled every case study and the homepage city into a shared chunk on every route.
- **Styling:** prefer existing styled-components and theme constants before adding new style primitives. Keep SCSS global changes broad and intentional.
- **Images:** static images live under `public/img/`; use accurate alt text for inspectable product and portfolio imagery.
- **Analytics:** use `trackEvent`, `trackLinkClick`, and existing tracked link components for navigational and CTA events.
- **Brand name:** render visible "ZICKONEZERO" through `src/components/BrandName.tsx` so ONE stays accent-colored without a text glow (ZICK**ONE**ZERO); keep plain text in titles, metadata, and analytics labels.
- **Role copy:** product engineering encompasses frontend and full-stack development; pair it with UX design rather than redundant development roles. Use `Product Engineer` and `UX designer` for people, `product engineering` and `UX design` for disciplines, and `Product Engineering` for navigation and section headings.
- **Effects:** clean up timers, animation frames, observers, and browser listeners. Respect reduced-motion checks where animation is significant, and give every new moving scene a still, readable reduced-motion state. Pause continuous work (canvas frames, audio) in hidden tabs, and keep scroll-driven updates in CSS custom properties or refs rather than React state.
- **City art:** all scenery, signage, and copy is original. Do not copy assets, logos, typefaces, or trademarked place and company names from games, films, or other brands.
- **Tests:** co-locate broad behavior tests in `__tests__/`; use React Testing Library for user-visible behavior and Jest for build utilities. Use `mockMatchMedia`/`restoreMatchMedia` from `src/test/matchMedia.ts` for reduced-motion and viewport cases, and `FakeAudioContext` from `src/test/fakeAudioContext.ts` for Web Audio code (jsdom has none). Keep the suite well under the 3-minute cap; a hung or slow test fails the run.
- **Validation:** do not mark work done while lint, typecheck, tests, or build fail. Browser tests are opt-in: run `npm run test:browser` or the manual Browser tests workflow only when the user asks, and keep them out of `npm test`, `npm run check`, and `ci.yml`.
- **Coding standards:** use `skills/coding-standards/SKILL.md` before implementation, refactors, UI state handling, error handling, performance-sensitive changes, tests, and reviews.
- **Agent briefs:** when meaningful project facts change, update `AGENTS.md`, run `npm run agent-briefs:sync`, and keep `CLAUDE.md` / `GEMINI.md` in lockstep.

## Maintaining this file

**Whenever you change the codebase in a way this document describes, update it in the same change.** Examples that require an update:

- Adding, removing, renaming, or re-homing top-level directories, route groups, feature folders, or build scripts.
- Changing root `package.json` scripts, CI/security workflows, lint/typecheck/test/build policy, or Node/npm assumptions.
- Changing static export behavior, sitemap behavior, analytics setup, or environment variables.
- Changing a file listed in [Key files map](#7-key-files-map), or adding something that belongs in it.

Treat `AGENTS.md` as the canonical source for the mirrored harness briefs. After updating it, run `npm run agent-briefs:sync` and `npm run agent-briefs:check` so [CLAUDE.md](CLAUDE.md) and [GEMINI.md](GEMINI.md) stay aligned.

Do **not** use this file for ephemeral notes, debugging logs, or session history. It is a durable project map, not a journal.
